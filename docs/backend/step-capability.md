# 01—07 节 45 步能力表（真实执行器实现后，依据源码静态核对）

- 来源：原用例 `TestCases/主流程/版本迭代主流程_测试用例.md` 01—07 节；源工程 `Tests/MainFlow/Sections/*.cs`、`MainFlowStepPlan.cs`、`MainFlowInputs.cs`、`Pages/*`、`Drivers/*`。
- 45 步 = 01—06 节 27 步 + 07 节 07.01—07.18（18 步）。
- “自动能力”指严格策略（三项全不选）下执行器应做到的动作与断言；人工策略只把硬件点改为网页确认，不降低软件断言。
- 状态来源必须是可观察事实（UIA 属性、页面显示、配方 XML、进程/PID、轴读数、运行提示），不能靠延时或按钮点击推断。
- **本表状态**：01—06 由源工程逐文件迁移并已编译；07 为本次新实现。两者都**尚未实机执行**，运行时定位唯一性与读数格式须现场首跑逐条确认；未实机验证的行在“现场首跑核对”列标注。

## 人工点汇总

- **仅人工策略**：02.02 回零与设备状态、04.01 平台无片确认、06.03 一键上片、06.04 上片完成核对、07.13 X 轴 20mm 点击、07.17 运行。
- **07.12/07.14/07.15/07.16/07.18 在跳过策略下整步跳过**：它们依赖实际采集到的点位、焦高与运行结果，没有点位时不能做软件断言，跳过不算通过。

## 尚存缺口（不冒充通过）

1. 02.02、06.04 的“完成状态”可读来源未在实机确认；严格策略读不到即阻塞。
2. 07 页无 AutomationId 控件的运行时唯一性未验证；定位规则是“标签 + 控件类型 + 同行几何归属”，歧义即阻塞并输出 UIA 树。
3. 07.16 调试图内容用“截图亮度/对比度统计”作为客观依据，只能证明图像区有内容，不能证明算法识别正确；算法正确性由 07.17 的“运行成功!”证明。
4. 07.13 依赖轴位读数格式（`X: 12.3456` 这类文本或多控件同行）；读不到即阻塞。
5. 07.05 三个字段都不可见时阻塞，需现场确认该版本是否真的不显示曝光/增益。
