# 01—07 节真实执行：交付与现场运行说明

本文是 JCRJZDH-6 本阶段（01—07 节 45 步）的交付入口说明：包在哪里、怎么起、怎么配、跑起来看到什么算真实执行、缺什么会阻塞、证据在哪。

## 1. 交付物与最短启动

发布包目录：`D:\WaferAoiUitest\dist`（由 `tools\build-release.ps1` 生成；不进版本库）。

```
dist\
  WaferAoi.UiTestTool.Web.exe        Web 宿主（只监听 127.0.0.1）
  start-real.cmd                     真实模式启动（默认 5180）
  start-simulate.cmd                 模拟模式启动（5181，仅联调）
  executor\
    WaferAoi.UiTestTool.Executor.exe 桌面执行器（net472 x64，UIA3）
  web\                               前端构建产物
```

最短启动（真实模式）：

```bat
cd /d D:\WaferAoiUitest\dist
set WAFER_AOI_UI_PASSWORD=<现场 admin 密码>
start-real.cmd
```

- 地址：`http://127.0.0.1:5180`
- 只允许本机回环访问；不开放局域网，无账号体系。
- **必须以管理员身份运行**宿主（执行器继承宿主身份）：被测程序与 UIA 操作需要提权；未提权时 01.01 会直接阻塞并写明原因。
- 密码只从环境变量 `WAFER_AOI_UI_PASSWORD` 读取，不落盘、不回显、不写日志。

模拟模式（`start-simulate.cmd`，5181）只验证契约与页面分支，**结论不得当作实机通过**，页面与报告都带 `simulated=true`。

2. 固定测试片：300mm、Notch、正面朝上、有水平黑切割道、**物料状态为切割后**，在 Loadport1 槽1。

6. 配方根目录与配置一致（`D:\GlobalConfig\Recipe`），否则 04.04 阻塞。

## 4. 运行模式与检查框

三个复选框可以全不选（默认：版本严格 + 硬件严格）。

| 选项 | 行为 |
| --- | --- |
| 跳过版本断言 | 01.02 仍执行并记为 `按用户要求跳过`，不伪造版本一致；同时放开版本号/日期必填校验 |
| 跳过硬件步骤 | 硬件动作与硬件状态核对记 `人工硬件跳过`；混合步骤仍执行能独立完成的软件断言 |
| 人工执行硬件步骤 | 硬件点暂停，等待网页确认（完成/阻塞/失败），其余软件断言照常执行；与“跳过硬件”互斥 |

**本阶段实机跑通 01—07 建议使用“人工执行硬件步骤”**：07.10 取景与 07.11 Z 调焦在原用例里就是人眼判断，严格策略在这两步会明确阻塞（见第 6 节），不会假装通过。

## 5. 真实执行做了什么（按节）

- 01—03：启动本轮 PID 并核对单实例；admin 登录；回零提示处理；版本号/编译日期与本轮安装记录逐字比较并截图；放片与槽位一致性由现场确认，软件侧回读 Loadport1。
- 04：新建配方 A（`REG_MAIN_FLOW_A_<yyyyMMdd_HHmmss>`），逐字段回读；提交前查重；落盘校验非空 rcp、同名资源目录、`FiducialType`、文件时间。
- 05：晶圆信息固定输入逐项写入并失焦回读；保存后轮询配方 XML 校验 11 个字段（含四个吹干时间与风刀状态）。
- 06：Loadport1/层1、关闭读码、对准角 0；一键上片按策略自动点击或现场执行；06.05 回读当前配方仍为 A。
- 07：切割道两点角度校正 18 步，见下节。

### 07 关键成功标准（不可用“保存成功”替代）

- 07.12/07.14：点位由“增加”按钮从实际轴位采集，列表行值与当前轴位四舍五入 4 位小数一致；两点同 Y，X2−X1≈20mm。
- 07.13：步距 1.000 点击 X 左箭头 20 次，读回 X 增加约 20.0000mm（±0.02mm），Y 不变，无限位错误。
- 07.15：保存后无“点位过少，至少需要2个点位”“保存失败”提示，列表仍 2 点、四参数仍 50/500/1/1。
- 07.16：点位“移动”回第一点后“采图调试”，无调试算法报错；图像区截图统计非全黑/全白且有对比度。
- **07.17：被测程序实际运行校正并返回“运行成功!”**，脚本核对提示文字后点击确定；无粗/精校准失败、飞拍超时、限位、标定或相机错误。
- 07.18：读取“角度偏移”“纠正后角度”，两者必须是有限数值（允许 0），**禁止手填**；截图与运行日志留证。

## 6. 已知阻塞与不冒充通过的点

| 位置 | 现象 | 原因与替代 |
| --- | --- | --- |
| 01.01 | 未提权或缺密码时阻塞 | 执行器在启动被测程序前做前置检查，如实报告缺哪项 |
| 02.02（严格） | 可能阻塞：“找不到可读的回零完成状态” | 已自动确认回零提示，但界面没有可读的“回零完成”文本；严格策略不以提示关闭代替回零完成。改用人工策略由现场确认，或提供该状态的可读来源 |
| 04.01（严格） | 出现“未检测到晶圆吸附”提醒时阻塞 | 严格策略没有可观察的“平台无片”依据，不能盲目点确定。改用人工策略确认平台为空 |
| 06.04（严格） | 可能阻塞：“找不到可读的上片完成状态” | 已触发上片，但界面无“上片完成/搬运完成”文本；不以“已点击”代替完成核对 |
| 07.10 / 07.11（严格） | 阻塞 | 取景与调焦依赖肉眼图像判断，脚本不能替代；用人工策略 |
| 07.05 | 曝光/增益三个字段都不可见时阻塞 | 页面未显示字段时没有可回读事实，不能记为已设置 1000/1/1 |
| 07.16 | 无法截取图像区时阻塞 | 缺图像宿主截图能力；证据里会写清缺哪个控件 |

以上都是**能力缺口**，不是“通过”。每次阻塞都会在步骤原因、`steps.log`、失败证据（UIA 树/截图/进程状态）里写明缺什么，便于现场一次补齐。
