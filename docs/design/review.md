# 设计质量审查报告

审查对象：`prototype.html`（高保真原型）、`tokens.css`、`design-tokens.md`、`components.md`、`wireframe.md`。
审查日期：2026-10-23。审查方式：静态走查 + 计算色值对比度 + 对照需求 WEB-01…WEB-12 逐条点检。
未做：真机浏览器截图对比、真实事件流联调、实机 27 步执行。

## 1. 结论

| 维度 | 结论 |
| --- | --- |
| 布局与信息层级 | 通过。三栏职责清晰，实时状态集中在中栏，详情不抢主流程；1560/1180 两档断点可退化为两栏/单栏 |
| 排版系统 | 通过。7 级字号上限（11—20px）、2 级行高，等宽数字避免跳动 |
| 色彩与对比度 | 通过。全部承载信息的文本 ≥ 4.72:1，满足 WCAG 2.1 AA；状态不依赖颜色单通道 |
| 间距一致性 | 通过。全部为 4 的倍数令牌；卡片内 16px、区块间 16px、页面 24px |
| 状态覆盖 | 通过（界面层）。11 种步骤状态、5 个运行阶段、4 类连接状态均有确定呈现 |
| 反模式 | 未发现需返工项，详见第 6 节 |
| 可实施性 | 高。组件与事件字段一一对应；仍待后端确认 4 项（第 7 节），不阻塞页面开发 |

**边界声明**：本审查只证明界面设计与需求映射一致，不证明执行器、硬件或实机 27 步可用；这些属于后端与现场验收（T04—T18）。

## 2. 布局审查

1. **首屏信息密度合理**：1440×900 下可见配置、选项、阶段、计数、约 10 行步骤，无需滚动即可判断“范围 27/184 步”和“当前是否在跑”。1080 高度约 15 行。
2. **危险/待处理信息位置正确**：人工确认卡与待现场处理卡放在步骤清单上方同一列，符合视线自上而下的操作顺序；未使用模态，现场人员能边看日志边确认。
3. **右栏职责单一**：只做“所选步骤的说明/断言/日志/证据 + 状态图例”。避免把汇总统计同时放两处导致数字不一致。
4. **长清单可用性**：章节头吸顶 + 章节进度（`3/5`），27 步不会迷路；未使用虚拟滚动（27 行不需要，减少实现复杂度）。
5. **一致性风险点**：`>1560px` 三栏时中栏最小宽度约 700px，步骤名+原因最长约 34 个中文字符可单行；超长原因在两行内截断为省略号需在后端限制 `reason` 长度（建议 ≤ 200 字符），页面保留完整原因于详情与报告。
6. **响应式取舍**：≤1180px 隐藏耗时列而非把清单改成卡片，保持“同一行读状态”的扫描效率；耗时仍在详情内可见。

## 3. 排版审查

| 检查项 | 结果 |
| --- | --- |
| 字号层级 | 11/12/13/14/16/20 六级，层级差 ≥1px；徽标 11px 为最小字号 |

## 4. 色彩与可访问性

实测对比度（相对亮度公式，WCAG 2.1）：

| 组合 | 比值 | 判定 |
| --- | --- | --- |
| 主文本 `#101828` / 白 | 17.75:1 | AAA |
| 次主文本 `#344054` / 白 | 10.46:1 | AAA |
| 正文 `#475467` / 白 | 7.69:1 | AAA |
| 辅助 `#667085` / 白 | 4.97:1 | AA |
| 辅助 `#667085` / `#f8fafc` | 4.75:1 | AA |
| 主色 `#1a56c4` / 白 | 6.62:1 | AA（大字号亦 AAA） |
| 白字 / 主色底 | 6.62:1 | AA |
| 成功 `#0f7b53` / `#e6f6ef` | 4.72:1 | AA |
| 跳过 `#6f5a00` / `#fcf6e3` | 6.19:1 | AA |
| 阻塞 `#9a3d00` / `#fdf0e7` | 6.18:1 | AA |
| 失败 `#b3261e` / `#fdecea` | 5.72:1 | AA |
| 等待 `#0b5cad` / `#e8f2fd` | 5.89:1 | AA |
| 中断 `#5b4a86` / `#f1edfa` | 6.59:1 | AA |

其他：

1. 状态同时具备文字 + 圆点 + 底色，色盲模拟下仍可区分“跳过/未执行”“阻塞/失败”。
2. 主色不参与结果表达；红/绿不用于装饰，避免“红色=危险按钮”与“红色=失败”语义冲突（失败图标只出现在状态与结论，实心红按钮不用于任何操作）。
3. 焦点环 `0 0 0 3px rgba(26,86,196,.28)` 在浅底与深色日志块均可辨；所有可点击行支持 Enter/Space。
4. `prefers-reduced-motion` 下关闭旋转与过渡；页面无自动轮播、无闪烁。
5. 日志区是唯一深色块（`#0e1726` + `#c8d3e2`，约 12:1），不与页面其他区域争夺注意力。
6. 纯图标按钮均有文字标签；状态区使用 `aria-live="polite"`（实现时用节流，避免每 500ms 播报耗时）。

## 5. 间距与组件复用

- 间距全部取自 `--sp-1…--sp-7`；未出现 5/10/14/18px 等游离值。
- 卡片结构与内边距统一（head 12/16、body 16、foot 12/16 且 sunken 底）；避免“每个卡片长得不一样”。
- 徽标、计数块、检查行、证据卡均在原型中复用同一套类名，前端可抽为 `Badge`、`CountCard`、`CheckRow`、`ArtifactCard`、`StepRow`、`LogView`、`Banner`、`Modal` 八个基础组件。
- 表格（历史）与清单（步骤）刻意采用不同密度：表格 8px 行内边距偏紧，清单 9px + 原因行，避免“27 步看起来像报表”。

## 8. 残余风险与后续验证

1. **步骤名称仍以契约为准**：本设计采用司小懿对照 `MainFlowStepPlan.cs` 的 27 步核对结果（编号/名称/章节），后端 T01 能力表与 `openapi.yaml` 定稿后如有差异，以契约为准；界面与状态语义不变，但验收文档需同步。
2. **事件协议未定稿**：`hardwarePolicy` 枚举、事件类型清单、`counts` 是否含 waiting/unknown 需与卫青确认（草案见 `components.md` 第 16 节）。若契约变化，仅影响字段绑定，不影响布局。
3. **1 秒内实时显示**是产品目标，需在联调时用真实 SSE 验证；原型不含性能结论。
4. **长时值守**：页面需考虑 8 小时不刷新场景（后端保活、前端重连退避），本次只定义了连接状态呈现。
5. **刷新恢复**：原型用 localStorage 模拟；正式实现必须以后端快照 + 事件序号为准，页面不得把本地缓存当作事实来源。
6. **无障碍实测**：建议在实现后用键盘走查一遍（配置→选项→开始→步骤行→确认卡→历史），并检查 200% 缩放下三栏是否退化为两栏。
